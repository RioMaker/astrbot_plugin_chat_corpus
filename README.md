# 对话语料库

为指定 QQ 群保存 AstrBot 收到的消息、图片和语音，并在管理后台导出能离线读取的 ZIP。支持 AstrBot 4.29.4 至 4.x 的 OneBot v11（aiocqhttp）适配器。

## 开始使用

1. 在 AstrBot WebUI 的插件管理中从 ZIP 安装，或把整个插件目录放入 `data/plugins/` 后重载插件。
2. 打开 **插件管理 → 对话语料库 → 语料归档**。页面会自动读取已连接 QQ 机器人加入的群，列出群名、群号和成员人数。按群名或群号搜索，勾选要记录的群，设置容量并保存。初始没有勾选任何群，多个群共用 1024 MiB（1 GiB）。
3. 在对应群使用的 AstrBot 配置文件中，选择支持图片输入的「图片转述模型」，启用「语音转文本」并选择语音识别提供商。采集后在「刷新状态」中可查看已识别、待识别、等待重试和已释放原件的数量。使用云端提供商时，附件会发送给所选服务。
4. 在同一页选择一个群或全部归档群，可按本地日期筛选，然后点击 **打包并下载 ZIP**。日期包含选定的首日和末日。页面会先显示已打包的消息、附件和字节数，再显示 ZIP 总大小和服务器已发送的数据量。请保持页面打开，浏览器接收完整个 ZIP 后即可保存。移出采集列表的群也可导出已存记录。

导出读取打包开始时已入库的消息和附件。打包期间可以继续采集和滚动清理，正在获取的附件随所属消息入库后可在下一次导出。关闭页面后，已生成且未领取的临时 ZIP 会在十分钟后释放。

「刷新群列表」会重新读取入群情况，保留当前勾选。多个机器人加入同一群时只显示一行。群列表缺少人数时，插件会再查询群资料，必要时按协议端返回的成员名单计数。页面只显示汇总人数。连接暂时中断时，已选群的设置仍然保留，未能取得的人数显示为「人数待获取」。

采集从配置生效后开始，覆盖适配器实际投递给插件的群消息。机器人离线期间的历史、协议端未回送的机器人发言，以及被框架在投递前过滤的内容，都可能缺席。导出含发言人 QQ 号、昵称、群名片及原文。将记录用于训练时，应按群成员知晓并同意的使用范围处理。

## 容量和媒体

- **关闭动态存储**（默认）时，写不下的新消息会被整条跳过并计数。已有记录继续可读，提高上限后即可继续写入。
- **开启动态存储**时，优先释放已保存识别文字的图片与语音原件。两者同级，共享文件按最近一次引用它的消息时间排序。空间一够就停止。混合消息可跳过放不下的新附件，保留正文。纯媒体新消息需要挤占历史文字时会跳过。仍需轮换消息时，先清仅剩占位的记录，再按发送时间从旧到新清文字，同一秒按接收顺序。只有识别文字的消息也按文字保留。
- 新附件在后台识别，重复文件复用同一结果。图片分别保存可读文字和画面描述，语音保存转写。旧库升级后原件继续可读，第一次遇到动态容量压力时进入补识别队列。未配置提供商、识别失败或结果为空时保留已有原件，约十分钟后重试。降低上限会立即清理可释放的数据，受保护的原件可能让用量暂时高于新上限。此时暂停存入放不下的新原件，优先尝试保存聊天文字。
- 图片和语音尽量保存协议端提供的原始字节。插件能读取内联 Base64 与 QQ 媒体链接，链接失效时再向 OneBot 请求媒体。某些协议端会将语音转成 MP3。文件和识别结果按 SHA-256 共享。释放原件后，再次收到同一文件会复用已有文字。最后一条引用移除后，共享的识别结果也随之释放。
- 过期、无法读取、格式无法识别或超过单条可用容量的附件，会在原消息段标记缺失原因，同行的文字和可取回的媒体仍会尝试入库。语音可保留 QQ 的 SILK 格式。
- 容量按已提交的 SQLite 数据库用量计算，包含消息、附件和索引。数据库位于 `data/plugin_data/astrbot_plugin_chat_corpus/corpus.sqlite3`。SQLite 写入日志（WAL）和操作系统临时目录里的媒体副本、下载包需要额外的临时磁盘空间，下载完成或中断后释放导出文件。

## 导出结构

| 包内路径 | 内容 |
| --- | --- |
| `messages.jsonl` | UTF-8，每行一个消息对象。按发送时间排序，保留原始消息段顺序及文字空白。 |
| `media/<sha256>.<扩展名>` | 当前导出范围内被消息引用的图片和语音。同一文件只出现一次。 |
| `manifest.json` | 格式版本、导出时间、群和时间范围、消息数、媒体文件数和缺失媒体段数。 |

每行的 `group_id`、`platform_id` 和 `self_id` 标识来源，`message_id` 标识消息，`timestamp` 是 Unix 秒，`received_ns` 是本机接收的 Unix 纳秒。`sender` 保存发言人的 `id`、`nickname` 和 `card`。按 `segments` 的原始顺序读取聊天文字和媒体识别结果，即可还原对话顺序。仍有原件的媒体段提供 `media.path`，路径相对于 ZIP 根目录。

@、回复目标 ID、表情也保留为消息段。合并转发会尝试展开一层并归档其中的图片与语音，更深的转发引用保留 ID。协议端无法展开时保留原转发 ID 并标记 `forward_status`。视频与一般群文件保存消息段信息。

格式版本 2 在原媒体段内附带 `recognition`。图片的 `ocr_text` 保存图中可读文字，`description` 保存画面描述。语音的 `transcript` 保存转写。群友输入的文字仍在文字段的 `data.text` 中，可按来源筛选训练语料。合并转发内的媒体使用相同结构。

媒体段的 `media.sha256` 和 `media.bytes` 标识原件。已释放的原件移除 `media.path`，标记 `media.missing = "capacity_evicted"`，识别文字仍在。因容量未接收的新附件标记为 `capacity_skipped`。其他缺失原因包括 `unavailable`、`unrecognized_format` 和 `over_limit`。清单记录已识别、已释放和所有缺失的媒体段数量。空范围也能导出有效 ZIP。

## 本地验证

在 Python 3.12 环境中安装 `requirements.txt` 和 `pytest`，运行 `python -m pytest -q`。安装 AstrBot 后，测试还会使用实际 OneBot 适配器事件、AstrBot 配置和 Dashboard 响应接口进行离线联测。
